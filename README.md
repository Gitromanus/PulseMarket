# PulseMarket — Python-движок + Electron UI

Десктопное приложение: очередь заданий, потоки браузерной автоматизации, отчётность, управление через Google Sheets.

**Статус:** M0–M3, M5, M6 закрыты (M4 «WB» пропущен по решению заказчика). Работает полный цикл «таблица → очередь → браузерный поток → Ozon → результаты → таблица» на Google Sheets, локальном Excel и тестовой таблице; есть ручной режим выкупа, планировщик и отчёт о ресурсах. Живой прогон Ozon с текущего IP площадка блокирует (403), нужен residential-прокси.

## Что уже работает

- Electron: настройки (Основные / Просмотр), рабочее окно с потоками, живым логом и результатами.
- Ядро на FastAPI: свободный порт, токен, WebSocket-события, история лога.
- SQLite (WAL): атомарный захват, lease, watchdog, восстановление после падения, лимит ошибок.
- Синхронизация с таблицей в обе стороны: pull по `ID`, push только изменений (`G:N`), лист «Выкупы» при добавлении в корзину. Тестовая таблица (JSON) или Google Sheets.
- **Браузерный слой:** Playwright Chromium с постоянным профилем, прокси из файла, профили active/done/noauth, реальное «Показать/Спрятать браузер» через Win32, humanizer (мышь, печать с опечатками, инерционный скролл).
- Провайдеры: `vanilla` (по умолчанию), `cdp` (подключение к антидетект-браузеру), `camoufox` (заглушка с понятной ошибкой).
- Корректное завершение: при выходе ядро останавливает прогон, закрывает браузеры и возвращает задания в очередь.

## Запуск

Требуется Python 3.12 и Node.js 18+.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m playwright install chromium

cd ..\ui
npm install
npm run dev
```

`npm run dev` собирает renderer + Electron main и запускает приложение. Ядро Electron поднимает сам на свободном порту и передаёт адрес с токеном через `%APPDATA%\pf-automation\runtime.json`.

Отдельно ядро (для отладки API): `cd backend; .\.venv\Scripts\python.exe -m app` — порт `PF_PORT` (по умолчанию 8765).

## Браузер

По умолчанию браузер в потоках выключен — прогон идёт демо-сценарием. Включение: «Настройки → Браузер → Открывать браузер в потоках = Да». Тогда каждый поток:

1. берёт профиль: с вероятностью «Использовать готовый профиль» — папку из «Активные профили», иначе создаёт чистый `noauth/auto-…`;
2. берёт прокси из `proxies.txt` (если файл указан и не пуст), иначе идёт напрямую;
3. запускает Chromium с `user_data_dir` профиля, локалью и часовым поясом из настроек;
4. открывает «Проверочную страницу», скроллит и «читает» её;
5. закрывает браузер и возвращает профиль/прокси в пул.

Профили выдаются на каждый прогон заново по кругу, а прокси **навсегда закрепляется за профилем** (`%APPDATA%\pf-automation\profile_proxies.json`): один профиль всегда выходит с одного IP, новые профили распределяются по пулу равномерно. Поэтому подряд идущие прогоны идут с разной парой «профиль + его прокси», а не с одним и тем же профилем, прыгающим между IP. Позиция обхода профилей сохраняется между остановками и запусками прогона; при старте приложения точка выбирается случайно.

Если прокси не открыл Ozon (`net::ERR_FAILED` / `ERR_HTTP_RESPONSE_CODE_FAILURE`), задание сразу не валится: профилю назначается другой свободный прокси, выдерживается пауза 10–20 с и делается ещё одна попытка.

Новые (ещё ни разу не запускавшиеся) профили можно создать и прогреть прямо в настройках: генератор делает пустые папки в active, а прогрев по очереди открывает их на Ozon (главная + поиск), чтобы появились куки. Прогрев идёт только при остановленном прогоне, примерно 20–40 секунд на профиль, и использует закреплённый за профилем прокси.

Проверка прокси открывает выдачу Ozon через каждый адрес из `proxies.txt` и помечает блок-страницу «Похоже, нет соединения» (HTTP 403 / incident). Результаты сохраняются в `%APPDATA%\pf-automation\proxy_check.json`; кнопка «Убрать заблокированные» удаляет только явно заблокированные строки и делает `.bak` файла прокси.

В настройках есть таблица прокси (статус последней проверки, сколько профилей закреплено) и таблица активных профилей с их прокси. Кнопка «Закрепить за профилями» раздаёт прокси тем профилям, у которых закрепления ещё нет, сохраняя уже существующие связки.

Кнопка «Проверить браузер» в настройках открывает одну сессию и возвращает заголовок, HTTP-код, профиль и HWND — быстрый способ проверить окружение.

«Показать/Спрятать браузер» работает так: по `user_data_dir` через psutil находится PID Chromium, через `EnumWindows` — HWND окна, дальше `ShowWindow(SW_HIDE/SW_SHOW)`. В headless и CDP-режиме кнопка вернёт понятную ошибку (окном управляет провайдер).

Ограничения M2:

- `camoufox` не подключён (нужен отдельный пакет и проверка отпечатков);
- `cdp`-провайдер написан, но не проверен на живом Dolphin/AdsPower — нет подписки;
- позиция товара в браузерном прогоне остаётся пустой: парсинг выдачи появится в M3.

## Ozon (M3)

Сценарий включается вместе с браузером и работает для заданий с `Маркетплейс = ozon`. Шаги:

1. гео из колонки «Гео» (URL города), опциональное подтверждение «Да, я здесь»;
2. выдача `https://www.ozon.ru/search/?text=…` (постранично `&page=N`), сбор карточек с накоплением при скролле — сетка виртуализирована;
3. позиция = сумма карточек предыдущих страниц + индекс на найденной; если товара нет за `Максимум страниц поиска` — ошибка `position_not_found`;
4. открытие карточки кликом по ссылке из выдачи (fallback — прямой URL);
5. фото (если включено), описание, отзывы с таймингом из настроек, лайк отзыва, избранное, сравнение, «Смотрите также», «Другие продавцы» — по процентам;
6. корзина, затем добивка времени до диапазона «Время на карточке».

Проверка и отладка:

```powershell
cd backend
.\.venv\Scripts\python.exe tests\test_selectors.py       # fallback селекторов, разбор SKU
.\.venv\Scripts\python.exe tests\test_ozon_fixture.py    # сценарий на реальном DOM из fixtures
.\.venv\Scripts\python.exe tools\ozon_smoke.py "наушники"  # живой прогон (нужен доступ к Ozon)
.\.venv\Scripts\python.exe tools\capture_ozon.py "наушники" # обновить фикстуры
```

Селекторы лежат в [[sourcecraft-file backend/app/flows/selectors/ozon.json]]: у каждого — цепочка вариантов (widget → css → aria → текст). Если не сработал ни один, ошибка `selector_not_found` с ключом, а не «тихий ноль». При любой ошибке сценария сохраняются `page.png`, `page.html` и `url.txt` в `%APPDATA%\pf-automation\artifacts\`.

Реальность антибота: с датацентрового IP Ozon отдаёт 403 уже на выдаче, все варианты headless/headed и User-Agent это не меняют. Для работы нужны residential/mobile-прокси из пула, прогретые профили и пауза между прогонами — код к этому готов, но проверить живьём с текущего IP сейчас нельзя.

Согласованность отпечатка (M2):

- **часовой пояс по умолчанию берётся из системы** (`timezone` пустой). Раньше был зашит `Europe/Moscow`, и на машине с UTC+5 браузер противоречил ОС и гео IP — сильный маркер. Заданный вручную пояс используется, только если заполнить поле; старый `Europe/Moscow` из настроек автоматически сбрасывается на системный;
- **движок — patchright** (по умолчанию): убирает CDP-след `Runtime.enable` и маркерные флаги; `PF_ENGINE=playwright` — аварийный откат;
- **браузер — установленный Chrome, затем Edge** (`channel = auto`), в крайнем случае Chromium из Playwright. UA и Client Hints родные, без подмены;
- **случайные, но стабильные для профиля** размер окна и devicePixelRatio — профили не выглядят клонами;
- **следы Playwright в `window` удаляются** init-скриптом (`window.playwright`, `__pwInitScripts`); `navigator.webdriver` вручную не патчим — это оставляет не-[native code] след;
- **челлендж ищется на каждом проходе** — в URL, заголовке, тексте и всех фреймах (`fab_chlg`, `abt-challenge`, `variti`, `antibot`, `captcha`), а не один раз после загрузки;
- **cookie-баннер и «Добавить адрес» закрываются** перед сбором выдачи и в карточке — они перехватывают клики;
- при ошибке в артефактах теперь есть `final_url.txt`, `final_text.txt` и `frames.txt` — объективный снимок того, что видел браузер;
- headless-режим помечается предупреждением в логе: для Ozon он заметнее.

Проверка прокси до прогона: `python tools/proxy_check.py --file proxies.txt --ozon` печатает внешний IP, страну, часовой пояс, задержку и результат открытия выдачи Ozon. Бесплатные публичные прокси из открытых списков для Ozon не годятся: они умирают за минуты, а живые всё равно в чёрных списках и видят ваш трафик (куки, корзину).

Диагностика расхождения «система ↔ браузер ↔ IP»: в логе старта печатаются пояс, движок и выбранный браузер, например `Движок: patchright, браузер: auto, часовой пояс: Asia/Yekaterinburg (системный)`.

## Ручной режим (M6)

Вкладка «Ручной режим» — для выкупов: открыть профиль с сохранёнными куками и прокси, оставить браузер оператору, закрыть после заказа.

- Профиль выбирается из `active` / `done` / `noauth` или создаётся временный безакк.
- Профиль, занятый потоком прогона, открыть нельзя — проверка по активным сессиям supervisor.
- Кнопки: «Показать/Спрятать» (реальный Win32), «Перейти» по URL, «Закрыть».
- Всё видно в логе: профиль, прокси, скрытие/показ, переходы.
- Таймаутов на сессию нет: оператор закрывает её сам, при выходе приложения все сессии закрываются.

Типичный сценарий выкупа: лист «Выкупы» → строка с профилем → «Ручной режим» → выбрать профиль → «Открыть браузер» (стартует корзина Ozon) → оформить заказ вручную → «Закрыть».

## Планировщик и отчёт (M5)

Кнопки в панели рабочего окна: **«Планировщик»** и **«Отчёт о ресурсах»**.

Планировщик:

- запускает прогон каждые N минут (5–1440), только если очередь не пуста и предыдущий прогон завершён;
- первый запуск — через интервал после включения, следующий виден в модальном окне;
- если прогон ещё идёт в момент срабатывания, окно сдвигается на интервал, а не наслаивается;
- настройки хранятся в `settings.json` и переживают перезапуск; таймер — нет, после старта приложения отсчёт начинается заново.

Отчёт о ресурсах: задания (очередь/готово/ошибки), прогоны (сегодня/успешно/ошибки), открытые потоки и ручные сессии, количество и память процессов Chromium, память ядра, размер БД и папки артефактов, профили по папкам, прокси в файле.

Лог переведён на окно рендера: в DOM живут только видимые строки (высота строки 18 px), поэтому 10 000 записей не тормозят; полный текст сообщения — в подсказке при наведении.

## Excel-таблица (.xlsx)

Настройка «Основные → Файл Excel (.xlsx)». Приоритет источников: Google (если заданы креды и ID) → Excel → тестовая таблица.

Колонки определяются **по заголовкам**, а не по позиции: поддерживаются синонимы («Кол заданий», «Требуется выполнений», «Позиция Факт», «Фактическая позиция», «Статус итог» и т.д.). Формат вашей таблицы подхватывается как есть:

| Кол. | Заголовок | Что делает бот |
|---|---|---|
| A | Дата | не трогает |
| B | SKU | читает ссылку, извлекает артикул |
| C | Ключевой запрос | читает |
| D | Использовать фильтр | игнорирует (пока) |
| E | Необходимое кол заходов | игнорирует |
| F | Город | читает как гео |
| G | Кол заданий | цель по выполнениям |
| H | Позиция Начальная | пишет первый замер |
| I | Позиция Факт | пишет последний замер |
| J | Кол добавлений в корзину | пишет счётчик |
| K | Кол лайков | пишет счётчик |
| L | Статус итог | пишет при завершении (Готово/Ошибка/Отмена) |
| M | Статус | читает команды оператора и пишет текущий статус |

Особенности:

- **Колонки ID нет** — ключ задания формируется как `excel:<лист>:<строка>`. Пока строки не сортируют и не вставляют, связь стабильна; если нужна устойчивость к сортировке, добавьте колонку `ID` — бот сам выдаст UUID.
- Перед первой записью рядом создаётся `table.backup-ГГГГММДД-ЧЧММСС.xlsx`.
- Если файл открыт в Excel, запись не пройдёт: в статусе синхронизации будет понятная ошибка, данные не потеряются.
- При первом добавлении в корзину создаётся лист «Выкупы» (если его нет). «Аккаунты» бот не создаёт.
- Если имя листа в настройке не совпадает с файлом, бот берёт единственный лист, **кроме служебных** «Аккаунты»/«Выкупы». Настройку «Лист заданий» можно не менять.
- Смена источника изолирована: задания из прежней таблицы получают статус `paused` и не попадают в новый файл (в отчёте видно «Приостановлено»).

## Таблица: тестовый режим и Google

Без сервисного аккаунта приложение использует `%APPDATA%\pf-automation\fake_sheet.json` — те же три листа (`ПФ2`, `Аккаунты`, `Выкупы`) и колонки. Файл создаётся при первом запуске с тремя заданиями `SHEET-2001…2003`.

Как только указаны существующий `.json` сервисного аккаунта и `ID` таблицы, бэкенд переключается на Google (таблица должна быть расшарена на `client_email`).

Правила обмена:

- строки ищутся по `ID` (UUID), строке без `ID` бот дописывает его сам;
- из листа читаются только операторские поля: маркетплейс, SKU, запрос, гео, «Требуется выполнений», «Статус»;
- счётчики, позиции, ошибку и время пишет только бот, диапазоном `G:N`;
- `Отмена` → задание снимается; `Ожидает` при недоборе → снова в очередь;
- запись только при изменении значений (таблица `sheet_state`).

Сброс тестовых данных: «Настройки → Сбросить тестовые данные».

## Лицензия (M7)

Ключ — строка `PF1.<данные>.<подпись>`: JSON с именем клиента, списком HWID и сроком, подписанный Ed25519. Подпись проверяется локально, поэтому приложение работает без интернета; приватный ключ есть только у поставщика.

1. Один раз создайте пару ключей:

```powershell
cd backend
.\.venv\Scripts\python.exe tools\make_license.py init
# печатает PF_LICENSE_PUBKEY=... и пишет license_keys\ed25519_private.pem
```

2. Клиент присылает HWID из вкладки «Лицензия» (кнопка «Копировать»). Ключ выпускается на 1–2 машины:

```powershell
.\.venv\Scripts\python.exe tools\make_license.py issue `
  --sub "ООО Ромашка" --hwid HWID-XXXX-XXXX-XXXX-XXXX-XXXX --days 365
.\.venv\Scripts\python.exe tools\make_license.py issue --sub "Иван" `
  --hwid HWID-A... --hwid HWID-B... --days 0      # 0 — бессрочно
```

3. Ключ вставляется во вкладке «Лицензия» → «Активировать». Там же показываются срок, остаток дней и режим.

Как устроена проверка:

- подпись неверна / истёк срок / чужой HWID → прогон и ручной режим не стартуют, в логе понятная причина;
- сервер (`license.server`) необязателен: без него ключ проверяется по подписи;
- с сервером приложение раз в 5 минут делает `POST /check`; если сервер недоступен, действует офлайн-допуск **7 дней** с последней успешной проверки;
- без публичного ключа (сборка из исходников) приложение работает в режиме разработки и пишет об этом в лог.

Публичный ключ попадает в сборку через `-PublicKey` (см. ниже) или переменную `PF_LICENSE_PUBKEY`; приватный `backend/license_keys/` в репозиторий и установщик не входит.

## Сборка установщика

Требуется Python-venv, Node и компилятор для Nuitka (Nuitka сам скачает MinGW64, если MSVC нет).

```powershell
# только ядро: build\backend\pf-backend.dist + smoke-проверка
powershell -ExecutionPolicy Bypass -File scripts\build-backend.ps1 `
  -PublicKeyFile backend\license_keys\ed25519_public.txt

# ядро + UI + NSIS-установщик в ui\release
powershell -ExecutionPolicy Bypass -File scripts\build-installer.ps1 `
  -PublicKeyFile backend\license_keys\ed25519_public.txt
```

Что происходит:

- Nuitka собирает `pf-backend.exe` (standalone) и проверяет `/api/health` на случайном порту;
- браузеры Playwright копируются в `build\backend\pf-backend.dist\browsers` (если установлены) — установщик не требует `playwright install` на машине клиента;
- electron-builder кладёт ядро в `resources/backend` и собирает установщик `PulseMarket-Setup-0.1.0.exe`;
- установщик ставится в профиль пользователя, ярлык «PulseMarket», данные остаются в `%APPDATA%\pf-automation` (историческое имя папки сохранено для совместимости) и не удаляются при удалении.

Приложение из установщика запускает `resources\backend\pf-backend.exe`; в режиме разработки — `backend\.venv` как раньше. Если браузеры не были установлены на машине сборки, выполните один раз `backend\.venv\Scripts\python.exe -m playwright install chromium` и пересоберите ядро.

## Диагностика

- **Ядро не стартует.** Проверьте `.venv`, `pip install -r requirements.txt`; логи идут в консоль Electron (`[backend] …`).
- **`playwright install chromium` не выполнен** — «Проверить браузер» вернёт ошибку с путём.
- **Chromium не появился в списке окон.** Проверьте, что `headless = Нет`; в headless управлять окном нельзя.
- **Ozon отдаёт `ozon_blocked` / antibot challenge.** IP заблокирован: нужен residential/mobile-прокси (гео РФ), 1–3 потока. Прогон делает паузу 15–25 с перед повтором и останавливается после второй такой ошибки; задания возвращаются кнопкой «↻ Повторить выполненные» (желательно после паузы 10–15 минут). Скриншот и HTML — в `%APPDATA%\pf-automation\artifacts\ozon-*`.
- **`ELECTRON_RUN_AS_NODE`.** `npm start` использует `scripts/start-electron.mjs`, снимающий эту переменную.
- **Данные**: `%APPDATA%\pf-automation\` — `settings.json`, `app.db`, `fake_sheet.json`, `runtime.json`, `profiles/`.
- **Снимок окна**: `PF_SHOT=path.png npm start` (опционально `PF_SHOT_DELAY=мс`).
