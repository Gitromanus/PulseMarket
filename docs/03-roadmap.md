# План работ и состав зависимостей

## Зависимости

`backend/requirements.txt` (установлено):

```
fastapi uvicorn[standard]
pydantic
aiosqlite
gspread google-auth
tenacity
loguru
```

Добавляется на M2: `playwright` (async API), `pywin32` (show/hide окна), `aiohttp` (проверка прокси и API провайдеров), `camoufox` (опционально).

`ui/package.json` (установлено): `electron`, `electron-builder`, `vite`, `react`, `react-dom`, `typescript`. На M5 добавляются `zustand` (состояние), `@tanstack/react-virtual` (лог на 10k строк), `recharts` (отчёт по ресурсам).

## Порядок, который экономит время

1. Сначала M1 (очередь) — без неё любой сценарий невозможно отлаживать параллельно.
2. Затем M2 на `vanilla` провайдере, чтобы не зависеть от подписки антидетекта.
3. Сценарии писать против интерфейса `Scenario`, с записью каждого шага в `runs.steps_json`. Без таймлайна разбор «почему не сработало» превращается в гадание.
4. Планировщик (cron/интервал) делать после M5: он нужен редко и просто обёртка над `/api/run/start`.

## Definition of Done для сценария

- [ ] шаги идемпотентны: повторный запуск после сбоя не ломает профиль;
- [ ] любой селектор — из `SelectorRegistry` с fallback-цепочкой и явной ошибкой `selector_not_found`;
- [ ] скриншот + HTML страницы в `artifacts/{run_id}/` при ошибке;
- [ ] тайминги только из настроек, никаких `sleep(300)` в коде;
- [ ] профиль всегда возвращается в пул (или помечается `banned`) в `finally`.
